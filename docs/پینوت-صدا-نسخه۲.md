# پینوت صدا — نسخه ۲ (نسخه‌ی ما)

> از شماتیک رسمی **نسخه ۲** استخراج شد:
> `files.waveshare.com/wiki/ESP32-S3-Touch-LCD-1.85C/ESP32-S3-Touch-LCD-1.85C_V2.pdf`

## ⚠️ چرا این فایل وجود دارد

شماتیکی که ماه‌ها از آن استفاده می‌کردیم **مال نسخه ۱** بود. برد ما نسخه ۲ است و بخش صدایش کاملاً فرق دارد.

## پینوت صدا

| سیگنال | GPIO | به کجا می‌رود |
|---|---|---|
| `I2S_MCLK` | **۲** | ES8311 پین ۲ · ES7210 پین ۵ |
| `I2S_BCK` | **۴۸** | ES8311 پین ۶ · ES7210 پین ۹ |
| `I2S_LRCK` | **۳۸** | ES8311 پین ۸ · ES7210 پین ۱۰ |
| `I2S_DIN` (میکروفن ← ESP32) | **۳۹** | ES7210 پین ۱۱ (SDOUT1) |
| `I2S_DOUT` (ESP32 ← بلندگو) | **۴۷** | ES8311 پین ۹ (DSDIN) |
| `PA_CTRL` (فعال‌سازی آمپ) | **۱۵** | NS4150B پین ۱ (CTRL) |
| `I2C SCL` | ۱۰ | هر دو چیپ |
| `I2C SDA` | ۱۱ | هر دو چیپ |

## چیپ‌ها

| چیپ | کار | آدرس I2C |
|---|---|---|
| `ES7210` (U12) | مبدل آنالوگ‌به‌دیجیتالِ میکروفن | `0x40` |
| `ES8311` (U9) | کدک صدا برای بلندگو | `0x18` — روی خود شماتیک نوشته شده |
| `NS4150B` (U10) | آمپلی‌فایر | — |

## ☠️ اشتباهی که کردم

از شماتیک نسخه ۱ برداشتم:

```cpp
SCK = 15   // در نسخه ۲ این «فعال‌سازی آمپلي‌فایر» است
WS  = 2    // در نسخه ۲ این MCLK است
SD  = 39   // این یکی تصادفاً درست بود
```

یعنی **کلاک را روی پایه‌ی فعال‌سازی آمپلی‌فایر می‌فرستادم** و `WS` را روی پایه‌ای که کدک `MCLK` انتظار دارد. چیپ هیچ‌وقت کلاک درستی نگرفت، پس هیچ داده‌ای نفرستاد.

خروجی صفرِ مطلق کاملاً با این می‌خواند.

## تنظیم درست

```cpp
Wire.begin(11, 10);          // SDA, SCL
es7210_init();               // ← بدون این، میکروفن ساکت است

i2s.setPins(48,   // BCK
            38,   // WS / LRCK
            47,   // DOUT — بلندگو
            39,   // DIN  — ميکروفن
            2);   // MCLK ← نسخه ۱ اصلا MCLK نداشت
i2s.begin(I2S_MODE_STD, 16000,
          I2S_DATA_BIT_WIDTH_16BIT, I2S_SLOT_MODE_STEREO);
```

برای بلندگو هم:

```cpp
es8311_codec_init();
pinMode(15, OUTPUT);
digitalWrite(15, HIGH);      // آمپلي‌فایر روشن
```

## ✅ نتیجه — میکروفن کار کرد (۱۹ شهریور)

بعد از اصلاح پین‌ها و اضافه کردن `es7210_init()`:

```
[گوش] چپ: -1..-1   راست: -1..-1   بلندي=0.0000  زمينه=0.0004   ← سکوت مطلق قبل از کلاک
[گوش] چپ: -133..159  راست: -114..128  بلندي=0.0019            ← اتاق ساکت
[گوش] 👏 دست!  بلندي=0.0997  زمينه=0.0009                      ← دست زدن
```

**حدود ۶۰ برابر جداسازی** بین صدای زمینه و دست زدن. تشخیص بدون خطا کار کرد.

## ☠️ باگ در مثال رسمی خود ویوشیر

مثال `08_esp_sr.ino` خط ۲۵:

```cpp
#define ES7210_ADC_VOLUME (40)
ESP_ERROR_CHECK(es7210_config_volume(es7210_handle, ES7210_ADC_VOLUME));
```

ولی در `es7210.cpp` خط ۳۵۸ شرط اعتبار این است:

```cpp
ESP_RETURN_ON_FALSE(volume_db >= -95 && volume_db <= 32, ESP_ERR_INVALID_ARG, ...);
```

**۴۰ از ۳۲ بزرگ‌تر است.** یعنی این خط در مثال رسمی همیشه خطا می‌دهد — و چون `ESP_ERROR_CHECK` دورش است، باید کرش کند.

در موچی خطایش را دیدیم:

```
[E][es7210.cpp:359] es7210_config_volume(): invalid volume range
```

ما `MIC_ADC_DB = 6` گذاشتیم (دو برابر شدن سیگنال).

**درس:** مثال رسمی هم منبع مطلق نیست. همان‌طور که شماتیک نسخه ۱ گمراه‌مان کرد، مثال رسمی هم می‌تواند باگ داشته باشد. هر عددی را با کدِ خودِ درایور چک کن.

## ☠️ باگ خودمان — کفِ نویز که بالا می‌رفت

نسخه‌ی اول ردیاب کف نویز این بود:

```cpp
baseNoise = baseNoise * 0.995 + rms * 0.005;
```

یعنی **خود صدای دست زدن هم وارد میانگین می‌شد**. در لاگ واقعی:

| رویداد | زمینه |
|---|---|
| دست اول | ۰٫۰۰۲۵ |
| دست دوم | ۰٫۰۰۲۹ |
| دست سوم | ۰٫۰۰۳۴ |

هر دست زدن کف را بالا می‌برد، پس دست بعدی باید بلندتر می‌بود. در اتاق شلوغ کم‌کم کر می‌شد.

اصلاح — فقط قاب‌های آرام وارد میانگین شوند:

```cpp
if (rms < baseNoise)                 baseNoise += (rms - baseNoise) * 0.05f;   // پایین: سریع
else if (rms < baseNoise * 2.0f)     baseNoise += (rms - baseNoise) * 0.002f;  // بالا: خیلی کند
// صدای بلند اصلاً حساب نمی‌شود
```

این باگ را **لاگ پیدا کرد، نه من**. اگر `MIC_CALIBRATE` را روشن نگذاشته بودیم دیده نمی‌شد.

## ☠️☠️ و نسخه‌ی دومش هم غلط بود — قفلِ خاموش

اصلاح بالا خودش باگ داشت، و بدتر: **بی‌صدا** غلط بود.

```cpp
else if (rms < baseNoise * 2.0f) baseNoise += ...
```

`baseNoise` از صفر شروع می‌شود و فوراً به کف ثابت `0.0004` می‌چسبد. نویز واقعی اتاق `0.0034` است.

```
0.0034 < 0.0008 ?   هرگز.
```

شرط هیچ‌وقت باز نمی‌شد. **ردیاب از لحظه‌ی روشن شدن قفل بود و اصلاً کار نمی‌کرد.**

در لاگ ۲۷ ثانیه‌ای دیده شد — عدد یک بار هم تکان نخورد:

```
زمينه=0.0004    زمينه=0.0004    زمينه=0.0004    زمينه=0.0004
```

و آن عدد دقیقاً همان کف ثابتِ نوشته‌شده در کد بود. مقایسه با لاگ قبلیِ همان اتاق (`زمينه=0.0017`) قطعی‌اش کرد.

**چرا خطرناک بود:** هیچ خطایی نمی‌داد، و اتفاقاً موچی را حساس‌تر کرده بود. در اتاق ساکت بهتر کار می‌کرد. فقط جای شلوغ لو می‌رفت.

### اصلاح — سقفِ گام به جای شرط

```cpp
float d = rms - baseNoise;
if (d < 0) {
  baseNoise += d * 0.05f;                        // پایین: سریع
} else {
  float up  = d * 0.02f;
  float cap = baseNoise * 0.01f + 0.000002f;     // هر قاب حداکثر ۱٪
  baseNoise += (up < cap) ? up : cap;
}
```

هر دو جهت همیشه باز است؛ جلوی پرش ناگهانی را به جای شرط، با محدود کردن اندازه‌ی گام می‌گیریم. یک دست زدن ۶ قاب است → حداکثر ۶٪، بی‌اثر. کولری که روشن بماند → چند ثانیه و پذیرفته می‌شود.

### 📌 درس

**شرطی که به خروجیِ خودش وابسته است می‌تواند قفل شود.**

همیشه بپرس: «اگر از بدترین حالت شروع کند، راهی برای بیرون آمدن دارد؟»

این سومین باگ پشت سر هم در همین ده خط بود. الگویش هم روشن است: هر سه بار وقتی پیدا شدند که **عدد واقعی** را دیدیم، نه وقتی که به کد نگاه کردیم.

## ☠️ باگ چهارم — شرط سکوت که دست زدنِ سریع را می‌کشت

بعد از اینکه آستانه را درست کردیم، کاربر گزارش داد دست زدنِ پشت سر هم کار نمی‌کند. لاگ مستقیم انگشت گذاشت:

```
· رد شد   بلندي=0.5188  قاب‌قبل=0.0248  ()
```

پرانتزِ **خالی** یعنی هر دو آزمون (بلندی و تیزی) قبول شده بود. پس مقصر شرط سومی بود: `CLAP_QUIET`.

| | |
|---|---|
| فاصله‌ی دست‌ها | ۱۷۰ میلی‌ثانیه |
| طول طنین هر دست | ۱۵۰ میلی‌ثانیه |
| سکوتی که کد می‌خواست | ۱۵۰ میلی‌ثانیه |

بین دو دست هیچ‌وقت سکوت نمی‌شد.

**حذف شد.** آن شرط برای فیلتر کردن صدای ممتد (تلویزیون) بود، ولی آزمون تیزی همان کار را بهتر می‌کند — چون سکوت را در بازه‌ی درست می‌سنجد: **یک قاب، ۱۶ میلی‌ثانیه**، نه ۱۵۰.

## ✅ تنظیم نهایی — سه آزمون

هر سه باید قبول شوند:

| آزمون | مقدار | چرا |
|---|---|---|
| نسبت به کف نویز | `> 6×` | سازگاری با اتاق‌های مختلف |
| حد مطلق | `> 0.110` | حرف زدن رد شود |
| تیزی حمله | `> 6× قاب قبل` | ضربه از صدای ممتد جدا شود |
| فاصله | `> 250ms` | طنین دوباره شمرده نشود |

اعداد از لاگ واقعی آمدند، نه از حدس:

```
دست زدن‌ها : 21x  7.2x  88x  41x  46x  15x  103x  6.4x  48x  45x
حرف زدن‌ها : 1.6x  2.3x  1.3x  ...
```

### تست نهایی — هر سه قبول

```
یک دست        →  جا خورد                     ✅
چند دست سریع  →  جا خورد → ذوق‌زده → خوشحال   ✅
صدا کردن اسم  →  · رد شد  (نرم)              ✅
```

آن `(نرم)` نکته‌ی اصلی است: صدای انسان **بلند بود** (`0.1138`، بالای آستانه) ولی **تیز نبود**. اگر فقط به بلندی تکیه کرده بودیم، صدا کردن اسمش هم جا خوردن حساب می‌شد.

### 📌 درس اصلی این بخش

**بلندی، دست زدن را از حرف زدن جدا نمی‌کند. سرعت جدا می‌کند.**

دست زدن در یک قاب (۱۶ میلی‌ثانیه) از سکوت به اوج می‌پرد؛ صدای انسان چند قاب طول می‌کشد تا بالا بیاید. این همان تفاوتی است که در شتاب‌سنج بین «ضربه» و «تکان» هست.

## ❌ تشخیص کلمه‌ی «موچی» — امتحان شد، کار نکرد، حذف شد

ارزش دارد ثبت شود تا کسی (از جمله خودمان) دوباره از صفر شروع نکند.

### چرا wake word واقعی ممکن نبود

از `ESP_Wake_Words_Customization` خود اسپرسیف:

> «مشتری باید دست‌کم **۲۰٬۰۰۰ نمونه‌ی صوتی** تهیه کند... بیش از **۵۰۰ نفر**، شامل مرد و زن از هر سنی و دست‌کم **۱۰۰ کودک**... اتاق ساکت زیر ۴۰ دسی‌بل، میکروفن با وفاداری بالا... معمولاً **دو تا سه هفته** آموزش... **هزینه دریافت می‌شود**.»

کلمه‌های آماده‌اش `Hi ESP` و چند کلمه‌ی چینی است. فارسی ندارد.

### پس روش جایگزین: شمارش عبور از صفر

ایده این بود که به جای معنی، به **شکل** صدا گوش بدهیم. «چ» یک صدای سایشی پرفرکانس است و موجش خیلی سریع‌تر از «م» از صفر عبور می‌کند. ارزان است — نه FFT، نه مدل، نه حافظه.

**سه طراحی پشت سر هم، هر سه غلط:**

| # | فرض من | چه شد |
|---|---|---|
| ۱ | بین «مو» و «چی» مکث هست | همه‌ی کلمه‌ها `هجا=1` — «موچی» یک صدای پیوسته است |
| ۲ | نیمه‌ی دوم خش‌دارتر است | برعکس: موچی ۰٫۴ ، مامان ۰٫۹ |
| ۳ | «وسط را دور بینداز چون گذار است» | وسط **دقیقاً جایی بود که «چ» می‌افتد** |

آن سومی از همه آموزنده‌تر است:

```
موچي (۶۰۰ میلی‌ثانیه)
 م  ـــ و ـــــــ  چ  ـــ ی ــــــــ
└─── ۴۰٪ اول ───┘ └وسط┘ └─ ۴۰٪ آخر ─┘
                   ↑
       چیزی که دنبالش بودم، اینجا بود
       و خودم انداختمش دور
```

### چرا ادامه ندادیم

داده‌ی واقعی جداسازی نشان می‌داد (موچی ۰٫۴ در برابر مامان/بابا ۰٫۹–۱٫۱) و **وسوسه این بود که مقایسه را برعکس کنم و بگویم درست شد**.

ولی آن می‌شد وصله زدن به چهار نمونه، نه فهمیدن. با چهار نمونه می‌شود هر آستانه‌ای را طوری تنظیم کرد که جواب بدهد.

### 📌 درس

وقتی سه طراحی پشت سر هم غلط درمی‌آید، معمولاً **سوال اشتباه است** نه عددها. هیچ مقدار `GAP_MAX_MS` نمی‌توانست طراحی اول را نجات دهد، چون مکثی که دنبالش بودم اصلاً وجود نداشت.

### به جایش چه داریم

موچی به **حضور صدا** واکنش نشان می‌دهد، نه به معنی:

| ورودی | واکنش |
|---|---|
| حرف زدن بیش از ۹۰۰ms | قرعه‌ای: `گوش مي‌دهد` یا `کنجکاو` |
| یک دست زدن | جا می‌خورد |
| دست زدن پیاپی | ذوق‌زده |
| دست زدن در خواب | بیدار می‌شود + خمیازه |
| بشکن | مثل دست زدن (برنامه‌ریزی نشده بود، از فیزیکش درآمد) |

## ☠️ باگ پنجم — شمارنده‌ی حرف زدن که هر کلمه صفر می‌شد

کاربر گزارش داد: «اصلاً گوش نمی‌ده.» و درست بود.

در پایان **هر کلمه** این خط بود:

```cpp
mic.talking = false;
```

و «کلمه» یعنی هر صدایی که ۱۳۰ میلی‌ثانیه سکوت دنبالش بیاید — تقریباً هر کلمه‌ی معمولی. پس شرطِ «۱٫۵ ثانیه حرف زدن» عملاً یعنی **یک کلمه‌ی ۱٫۵ ثانیه‌ای بدون نفس کشیدن**. هیچ‌وقت نمی‌شد.

اصلاح: مکث کمتر از `TALK_BREAK` (۶۰۰ms) قطع حساب نمی‌شود.

## ✅ تایید نهایی سقف گام در کف نویز

در لاگ نُه دست زدنِ پیاپی:

```
13:07:49  زمينه=0.0028
13:07:53  زمينه=0.0074
```

کف دو و نیم برابر شد ولی **هر نُه دست گرفته شدند**. در نسخه‌ی بدون سقف، کف بی‌مهار بالا می‌رفت و دست‌های آخر از دست می‌رفتند.
